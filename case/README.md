# 贯穿案例

一本速记应用。从「打开就能写」长到四十个文件，再被修剪回八个。

## 跑起来

```bash
cd case
npm install
npm run dev          # 打开 http://127.0.0.1:5180/v1.1/
```

每个版本是独立目录，直接访问 `/v0.1/`、`/v0.2/`……

**需要构建步骤。** 浏览器不执行 TypeScript，所以不能双击 HTML 打开。样式是共用的 `case/style.css`，取自 `design/note-app.html` 那套视觉语言。

五个版本共用同一个 localStorage 键，所以在一个版本里写的笔记会出现在另一个版本里。想从干净状态开始，在控制台执行 `localStorage.clear()`。

## 版本对照

| 版本 | 形态 | 对应章节 |
|---|---|---|
| `v0.1/` | 1 个文件 44 行，能用 | 第 00 章（起点） |
| `v0.2/` | 7 个文件 149 行，"专业"但不必要 | 第 00 章（要拆的对象） |
| `v0.3/` | 加渲染层；两份对照写法 | 第 05 章 |
| `v0.4/` | 六条渲染规则；分支版对数组版 | 第 06 章 |
| `v1.1/` | 6 个文件，终点 | 第 16 章 |

演进理由见 [CHANGELOG.md](CHANGELOG.md)。

## 写进书里的一个真实副作用

`v0.2` 的重构把 `v0.1` 的 HTML 转义弄丢了。149 行比 44 行更不安全，而且没有任何地方会提醒你。详见 `v0.2/README.md`。

## 中间章节为什么不各有一版

第 07–13 章讨论的问题（参数膨胀、包装、状态同步、依赖创建、改动面）在 `v0.2` 那份代码里已经全部存在，不需要再各建一个版本。

只有代码真的变了的地方才建版本。为每章各造一个版本会让 `case/` 变成一个演示集，而它应该是一份真实的演进记录。
