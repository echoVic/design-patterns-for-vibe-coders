# 贯穿案例

一本速记应用。从「打开就能写」长到四十个文件，再被修剪回八个。

## 跑起来

```bash
cd case
npm install
npm run dev          # 打开 http://127.0.0.1:5180/v0.2/
```

每个版本是独立目录，直接访问 `/v0.1/`、`/v0.2/`。

## 版本对照

| 版本 | 形态 | 对应章节 |
|---|---|---|
| `v0.1/` | 1 个文件 44 行，能用 | 第 00 章（起点），第 16 章（终点） |
| `v0.2/` | 7 个文件 149 行，"专业"但不必要 | 第 00 章（要拆的对象） |

**v0.2 里有一个真实副作用**：重构把 v0.1 的 HTML 转义弄丢了。149 行比 44 行更不安全。详见 `v0.2/README.md`。

## 后面的版本

每章一个 commit，章末打 tag（`ch-04`、`ch-05`…）。读者可以 `git checkout ch-07` 看到那一刻的代码。

`CHANGELOG.md` 记「哪一章改了什么、为什么」，等第 04 章开写时建立。
