# AI 的实际回答

书里几处说「我把这段丢给 AI，它给了我 X」。这个目录是那些回答的**原件**，不是转述。

## 为什么要有这个目录

第 00 章和第 06、07 章都建立在一个判断上：**AI 倾向于给出比需求更多的抽象。** 这句话如果只是作者的观察，读者只能选择信或不信。

放上原件，读者可以自己看：

- 它到底给了几个文件
- 它的答案在什么意义上是对的
- 它多做了什么

## 两次实验

### `branch-refactor/` —— 第 06 章

**输入**：`../v0.4/src/render/branches.ts`，六条 `if`，每种语法一个开关。

**请求**：「分支太多了，帮我整理一下。」

### `editor-refactor/` —— 第 07 章

**输入**：一个十二个位置参数的 `Editor` 构造函数。

**请求**：「这个构造函数参数太多了，帮我整理一下，以后好扩展。」

## 怎么做这两次实验的

每次都是**独立会话**，只给代码和那句话，不给任何关于这本书的上下文。要求里明确写了「不要揣测这次任务有什么别的意图，也不要刻意选择某种风格」。

这是为了让结果可复现、也不带倾向。**同一个请求你去做，大概会得到类似但不完全一样的东西**——这正是这些答案的性质：它们是分布的样本，不是唯一的正确答案。

## 一句话

**这两次回答都不是错的。** 它们各自解决了一个真问题。这本书要讨论的是：**它们解决的问题，是你此刻的问题吗？**
